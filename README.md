## How I Approach a Requirement

1. Clarify the business problem, users, scope, assumptions and dependencies.
2. Map the current and proposed process, including alternate and exception paths.
3. Write functional requirements and user stories with measurable acceptance criteria.
4. Identify data, security, notification, integration and reporting considerations.
5. Prepare positive, negative, boundary and regression test scenarios.
6. Support UAT, triage defects, document decisions and confirm release readiness.
